### This run — Phase 21 (palette fuzzy match)

**1. `fuzzyScore()` function**
- O(n) greedy left-to-right character matcher. Returns -1 if not all
  query characters appear in the target in order; otherwise returns a
  non-negative score with bonuses for:
  - Word-boundary matches (+5): start of string, after space/hyphen/slash
  - Consecutive matched characters (+3)
  - Near-start matches (+2): first 4 characters of the target
- No backtracking, no dynamic programming — appropriate for ~15 palette
  items.

**2. `fuzzyScoreItem()` helper**
- Scores a query against a palette item's `label`, `description`, and
  `keywords`, returning the best score across all three.

**3. Two-pass filter in the query branch**
- First pass: exact substring matches (same as before) — these always
  rank at the top for precise relevance.
- Second pass: fuzzy matches on items not already matched by substring,
  sorted by descending score.
- Result: `filtered = [...substringHits, ...fuzzyHits]`. This means
  "dsh" → Dashboard, "ses" → Session Timer, "lin" → Lineups, "athl" →
  Athletes all work. Typos like "dashbaord" won't match substring but
  will fuzzy-match since all characters appear in order.

### This run — Phase 15 (new phase beyond the roadmap)
CLAUDE.md's "definition of phase done" includes "no blank screen / route
crashes". Two gaps against that bar existed on HEAD:
1. No route-level error boundary. A render error inside any lazy chunk (or a
   chunk-load failure on a flaky network) would propagate to the React root
   and blank-screen the entire app — including the sidebar/top-bar, leaving
   the user with no way back to a working surface.
2. The `*` catch-all route silently `<Navigate to="/" replace />`'d on any
   unknown path. That masks broken bookmarks, hides routing bugs, and breaks
   the mental model of "what URL am I on".

This run closes both.

**1. `src/shared/layout/ErrorBoundary.tsx` (new)**
- React class component (only class in the repo — required by React's error
  boundary contract). Reads exclusively from `THEME.*` tokens.
- `getDerivedStateFromError` + `componentDidCatch` — logs a tagged
  `[synth] route error` payload to the console with the `label` prop so the
  trace is easy to find in devtools. Placeholder for a future Sentry ship.

  caller-supplied label), Fraunces serif headline, Instrument Sans copy, a
  monospace error-message pre block (max-height 140 px, scrollable), and two
  buttons — **Retry** (clears local state, re-renders children, so cached
  chunks recover without a full reload) and **Back to home** (hard
  `window.location.assign('/')` to reset Suspense/store state on the way out,
  the safer default once something has already gone wrong in the tree).
- Accepts an optional `label` prop so each route's boundary carries a short
  hint about *where* the crash happened — matches synth's "provenance on
  every surface" design principle.
